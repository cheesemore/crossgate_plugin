# 客户端更新规则（cross ↔ crosscopy）

> 适用游戏：魔力宝贝：序章（cg37）
> 规则脚本：`tools/cross_update.py`
> 本文件与脚本一起提交到 git，作为每次客户端更新的固定操作流程。

## 目录约定

| 名称 | 路径 | 用途 |
|---|---|---|
| CROSS | `E:\cross\魔力宝贝：序章` | **实际游戏目录**（日常玩、打补丁） |
| CROSSCOPY | `E:\crosscopy\魔力宝贝：序章` | **纯净官方副本**（跑官方更新器专用，**永远不打补丁**） |

- 路径可用环境变量覆盖：`CROSS_ROOT`、`CROSSCOPY_ROOT`。
- `E:\crosscopy` 为 `E:\cross` 的完整镜像（含 crossgate_plugin 仓库、发布plugin、游戏目录），其中游戏目录保持官方原版。

## 为什么要有 crosscopy

官方更新器（Update.exe）在**已打补丁的客户端**上跑会互相干扰：更新器可能校验文件或覆盖我们的 hotfix / 补丁 DLL。因此：

1. 平时在 **CROSS** 上玩（带补丁）。
2. 客户端更新时**只在 CROSSCOPY 上跑官方更新器**（保持纯净，更新器才能正常计算/写入）。
3. 对比后把官方新文件同步回 CROSS，再重新打补丁。

## 更新流程（每次官方更新）

按顺序执行以下步骤：

### 1. 先还原 CROSS 到官方原版

```bash
# 先关闭游戏（脚本会检测 cg37.exe 是否在运行）
python tools/cross_update.py restore
```

效果：
- `hotfix.dll.bytes` ← `hotfix.dll.bytes.orig`（回到官方原版）
- 移走全部补丁产物（`SeqChapter*.dll.bytes`、`battle_appear.json`、`seqchapter_*.txt` 等）到 `_seq_patch_backup_<时间戳>/`
- 清除补丁状态 `combo_patch_state.json`

> 若 `.orig` 缺失，脚本会告警并跳过还原，需手动处理。

### 2. 等待用户在 CROSSCOPY 中手动更新

- 打开 `E:\crosscopy\魔力宝贝：序章\Update.exe` 跑官方更新。
- **不要**在 CROSS 里跑更新器。
- 更新完成后，用 `status` 确认版本：

```bash
python tools/cross_update.py status
```

关注 `hotfix.dll.bytes` 体积是否变化、`更新包` 是否出现新的 `cg37-1-YYYYMMDDHHMMSS.setup`。

### 3. 对比 CROSS 与 CROSSCOPY，输出报告

```bash
python tools/cross_update.py diff          # 快速（按体积比对）
python tools/cross_update.py diff --full-hash   # 全量 hash（慢，但精确）
```

报告会：
- 分三组：**官方新增** / **修改** / **cross 独有**
- 每组内把 **反外挂重点文件**（`!!!` 标记）单列：
  - `GameAssembly.dll`（IL2CPP 原生核心，反外挂最敏感）
  - `cg37.exe`、`UnityPlayer.dll`、`baselib.dll`
  - `hotfix.dll.bytes` / `hotfix.core.dll.bytes` / `assembly-csharp*.dll.bytes`
  - `globalgamemanagers`、`il2cpp_data\Metadata\global-metadata.dat`
  - `*.setup`（更新包，可看版本号）
  - 新增的 `.exe` / `.dll`（可能新增反外挂组件）
- `install\` 更新器缓存单独列出（跨版本后旧缓存无意义，sync 时安全清理）
- 报告同时保存到 `tools/update_reports/cross_update_<时间戳>.txt`

### 4. 用 CROSSCOPY 更新 CROSS

```bash
# 先关闭游戏
python tools/cross_update.py sync --dry-run   # 先预览
python tools/cross_update.py sync             # 正式同步
```

效果：
- 复制官方**新增 + 修改**文件到 CROSS（含新的 hotfix.dll.bytes、GameAssembly.dll 等）
- `install\` 旧更新缓存镜像对齐（删除 CROSS 独有的旧缓存，如 `cg37-1-20260722110614-simple`）
- **不删除** CROSS 中除 install 缓存外的独有文件（保护用户数据）

### 5. 在 CROSS 下重新打补丁（DLL 免拷贝）

- 打开补丁 GUI（`魔力宝贝序章补丁\scripts\seqchapter_combo_gui.py` 或傻瓜包）。
- 关闭游戏 → **初始化**（会自动用新版 hotfix 重建底稿：neworig / .orig / 工具体积常量）→ **应用补丁**。
- 补丁流程会把外部 DLL（SeqChapter 系列）**直接部署到 CROSS 的 hotfixdata**，无需手动拷贝 DLL 进出游戏目录。

> 注意：客户端更新后 `hotfix.dll.bytes` 体积变化时，初始化会自动更新 `patch_common.EXPECTED_SIZE` / `HotfixSize.Expected` 并重建补丁引擎。若新版反外挂发生变化，请先核对 diff 报告中 `!!!` 项再打补丁。

## 反外挂关注要点

每次更新的 diff 报告重点核对：

1. **GameAssembly.dll 是否变化** —— IL2CPP 原生层，通常每版必变；大幅变化说明可能有反外挂逻辑改动。
2. **hotfix.dll.bytes 体积变化** —— 需要重新初始化底稿并重打补丁。
3. **新增的 `.exe` / `.dll`** —— 警惕新增反外挂组件（NPGameDLL、ProcessPick 等原生插件目录 `Plugins\x86_64\`）。
4. **il2cpp 元数据**（`global-metadata.dat`）变化 —— 原生符号变化。

## 加速补丁与反外挂（kill-report）

- **所有带战斗加速的补丁，默认都携带"掐断倍速上报"补丁**（`kill-report`）：
  - 把官方检测方法 `GmManager.CheckTimeScaleWarning` 与上报方法 `NetManager.SendTimeScaleWarning` 打成空方法（首指令 `ret`）。
  - 官方唯一检测链：`StartTimeScaleCheck → CheckTimeScaleWarning（读 BattleTimeScale>1.0）→ SendTimeScaleWarning（Web 上报）`，全量扫描确认无旁路、无反射调用、无字符串按名查找。
- 实现位置：`tools/hotfix_patcher/VipTimeScaleIlPatcher.cs`，`killReport` 参数默认 `true`；Python 侧 `apply_vip` 不传 `--no-kill-report`，因此**只要走了战斗倍速/心跳回传补丁，自动携带**。
- 只有显式需要关闭时才传 `--no-kill-report`（**不要默认关闭**）。
- 纯玩法补丁（抓宠/卖银币/日常等，不含加速）不受影响，无需 kill-report。
