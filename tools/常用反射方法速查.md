> 每项标注实现状态：**✅ 已实现**（现有代码可用）/ **⚠️ 协议已确认未封装**（只有协议档案）。

## 1. 查询背包内某个格子的道具名 ✅ 已实现

**入口**：`PlayerDataHolder.GetItemDatasFromUid(string uid)` → `List<Com_Item>`（静态，含 Public/NonPublic）。

- 背包格下标：身上装备 0–7，背包 8–67（60 格）。
- 每个 `Com_Item`：`useFlag`（1=有道具）、`data`（`Proto_ItemData`）。
- 道具名取法两种：
  1. `data.Name`（`Proto_ItemData.Name` 字段，反编译 `hotfix.decompiled.cs:49440` 确认）—— 直接读格子道具名；
  2. `data.Id` → `ConfigManager.GetTbItemConfig().GetOrDefault(itemId).Name`（`ItemConfig.Name`，反编译 `502876` 确认）—— 按道具 ID 读配置名。

**现有代码参考**：
- `SeqChapterAutoStall.cs::GetItemDatas(uid)` + `CollectCandidates()`（读背包 [8..67]）
- `SeqChapterTestUi.cs::CheckEquippedMelee`（`GetMember(data, "Name")` 直接读格子道具名）
- `SeqChapterHelperBridge.cs::TryCollectSealCards`（读背包 + `useFlag` 过滤）

```csharp
var items = FindType("PlayerDataHolder")?.GetMethod(
    "GetItemDatasFromUid", BindingFlags.Public | BindingFlags.Static | BindingFlags.NonPublic)
    ?.Invoke(null, new object[] { uid }) as IList;
var item = items[bagIndex];                       // Com_Item
var data = GetMember(item, "data");               // Proto_ItemData
var name = Convert.ToString(GetMember(data, "Name") ?? "") ?? "";
```

## 2. 丢弃某个道具 ⚠️ 协议已确认，代码未封装

**游戏侧做法**（反编译 `hotfix.decompiled.cs:30895-30903, 329289`）：

```csharp
Manager<ItemManager>.Instance.SendBackPackMessage("丢弃物品", index, num, uid);
```

- 发送 `LSSPROTO_BACKPACK_FUNC` = **2001**，`Proto_CS_Backpack`
- 字段：`Type="丢弃物品"`，`Haveitemindex=index`（背包格下标），`Num=num`（数量），`KUid=uid`
- 入口源头：背包操作面板 `ItemOperatePanel.DropItem(num, info)`（`329289`）→ `SendBackPackMessage`

**DLL 反射封装**（未封装，需要时照此写）：

```csharp
var itemMgr = GetManagerInstance("ItemManager");
var m = itemMgr?.GetType().GetMethod("SendBackPackMessage",
    BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic,
    null, new[] { typeof(string), typeof(int), typeof(int), typeof(string) }, null);
m?.Invoke(itemMgr, new object[] { "丢弃物品", bagIndex, num, uid });
```

> 注意：这是「背包操作」类丢弃（回收站式），不是丢到地上。丢地上是 `Proto_CS_DropItem`（`LSSPROTO_DROP_ITEM_FUNC`=18，带 X/Y 坐标）。

## 3. 接收 NPC 更新（读缓存）✅ 已实现；服务端确实主动广播

### 结论
服务端会主动广播 NPC/角色/地图对象更新，客户端维护在
`EntityDataHolder.characterDatas`（`Dictionary<int, CharacterData>`，objindex → 数据）。
DLL 轮询读该缓存即可感知 NPC **出现 / 移动 / 消失**（含地图上突然刷出的 NPC）。

### 广播协议（服务端 → 客户端，客户端已有回调自动写缓存）
| 协议 | 编号 | 回调 | 作用 |
|---|---|---|---|
| `LSSPROTO_UPDATE_OBJ_FUNC` | 29 | `OnUpdateObjCallback` | NPC/角色出现、移动、属性变化 → 写/刷 `characterDatas`（`RefreshCharacterXY`） |
| `LSSPROTO_CLEAR_OBJ_FUNC` | 32 | `OnClearObjCallback` | NPC/角色消失 → `EntityContainer.Remove` → 清 `characterDatas` |
| `LSSPROTO_OBJ_ADDITIONAL_FUNC` | 31 | `OnObjAdditionalCallback` | 附加动作（走/跑/切换动作） |
| `LSSPROTO_MAP_FUNC` | 3 | `OnMapCallback` → `lssproto_M_recv` | 进图全量推地图 + NPC 实体 |
| `LSSPROTO_MAP_UPDATE_FUNC` | 3035 | `onMapUpdateCallBack` | 地图格/tile/object/event 增量更新 |

> 依据：反编译 `hotfix.decompiled.cs`（28130-28132 Register 三个 OBJ 回调；311721 OnMapCallback；311792 onMapUpdateCallBack）。

### DLL 读缓存方式（已验证，见 `SeqChapterHelperBridge.cs::ScanNpcsToCache`）

```csharp
var dict = GetStaticProperty("EntityDataHolder", "characterDatas") as IDictionary;
// 兜底：GetStaticField("EntityDataHolder", "<characterDatas>k__BackingField")
foreach (DictionaryEntry e in dict) {
    var cd = e.Value;                       // CharacterData
    var objindex = Convert.ToInt32(GetMember(cd, "objindex"));
    var name = Convert.ToString(GetMember(cd, "name"));
    var x = Convert.ToInt32(GetMember(cd, "x"));
    var y = Convert.ToInt32(GetMember(cd, "y"));
    var npcindex = Convert.ToInt32(GetMember(cd, "npcindex"));  // != -1 表示是 NPC
    var charEntityType = GetMember(cd, "charEntityType");       // CharacterEntityType
}
```

- 判断是不是 NPC：`npcindex != -1`（`EntityContainer.Remove` 里就是用它区分 NPC，见 `301128-301135`）。
- 注意：DLL 运行时**不要**自己 `NetManager.Register` 注册网络回调（现有 DLL 无此先例，注册时机/生命周期易出问题）；统一用「读缓存」方式轮询。
