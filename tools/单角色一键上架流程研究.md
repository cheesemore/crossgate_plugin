# 单角色一键上架 — 流程可行性整理

> 依据：`tools/hotfix_ilspy/hotfix.dll.bytes.decompiled.cs`
> 日期：2026-08-09
> 目标：单角色（当前主操作号）一键完成「回城 → 寻找摊位 → 收摊重摆 → 按定价上架背包可售道具」全流程。
> **状态：已实现**（2026-08-09）。实现见 `tools/seqchapter_auto_stall/SeqChapterAutoStall.cs`（DLL，面板脚本页「一键上架」按钮 + IPC 批量预留）；补丁子命令 `auto-stall-external-patch`；定价配置 `tools/gen_auto_sell_price_cfg.py`。本文件保留为协议依据，实现细节与改价流程见 §11。

## 0. 总览：流程能否走通？

| # | 步骤 | 能否走通 | 关键协议 / 数据 | 备注 |
|---|---|---|---|---|
| 1 | 判断自己已出摊 | ✅ | `StallManager.OpenStall(uid)` → 响应 `Proto_SC_Street.Status` | Status==3 未摆摊；1 出摊中；2 到期 |
| 2 | 判断非组队，组队则退出 | ✅ | `playerEntity.IsParty()` / `IsLeader()`；`TeamManager.SendOperation("离开队伍"/"解散队伍", uid)` | 队长解散、队员离开 |
| 3 | 回城到法兰城 | ✅ | `RoleManager.SendMenu(3, "-1")`（`Proto_CS_Menu{Func=3,Data="-1"}`） | 摆摊硬性要求法兰城（mapId==0 && floor==1000） |
| 4 | 飞到摊位 | ✅ | `StallManager.SendStallMessage(uid, "寻找摊位")` | 服务端直接传送，无需坐标 |
| 5 | 收摊 → 0.1s → 重摆 | ✅ | `SendStallMessage(uid, "收起摊位")` → 延时 → `SendStallMessage(uid, "我要摆摊")` | 重摆用于重置摊位时间；**不用「增加时间」续费（要钱）**；重摆失败/卡位置即停转人工 |
| 6 | 读剩余空格数 | ✅ | 摊位商品上限 **20**；剩余 = 20 − `Info.List` 中 `Status!=4` 的数量 | 客户端 `PutItemOnShelf` 里 `num >= 20` 报「商品数量不能超过20」 |
| 7 | 遍历背包可售道具按定价上架 | ✅ | 遍历 `GetItemDatasFromUid(uid)[8..67]`（60 格背包）；**只上架表单内装备**（有定价）；可售判定见 §7 | 表单外道具/宠物/料理一律不上架（无定价） |
| 8 | 摊位满或无道具可上架为止 | ✅ | 每上架成功一次后重新查询摊位状态，更新剩余空格；或一次性把全部可上架项构造进 `"上架摊位"` 列表 | 见 §6 两种实现策略 |

> **结论：全流程每一步都有对应协议，可以走通。** 下面是逐项依据与需要注意的坑。

## 1. 判断摊位状态

**发送**（`StallManager.OpenStall(uid)`）：

```csharp
Proto_CS_Street {
  1: string Type = "摊位状态";
 99: string KUid = uid;
}
// → LSSPROTO.LSSPROTO_STREET_FUNC (1013)
```

**响应** `Proto_SC_Street`：

```csharp
Proto_SC_Street {
  1: string Type;
  2: int    Status;      // ★ 摊位状态（顶层）
  3: Proto_commodityInfoArr Info;  // {List, Id, Name, ObjIndex}
  6: int    Time;        // 剩余摆摊时间
  9: string Name;        // 摊位名
 10: string Owner;       // 摊位主人 uid
 99: string KUid;
}
```

**Status 语义**（`StallPanel` 管理按钮逻辑 `OnClickManageItemBtn` / 初始化）：

| Status | 含义 | 客户端行为 |
|---|---|---|
| 1 | **出摊中** | 显示「摊位管理」按钮（可管理/改名/形象/日志/找摊位） |
| 2 | **到期未续** | 显示「增加时间/收起/改名/形象/寻找摊位/日志」按钮 |
| 3 | **未摆摊** | 按钮显示「我要摆摊」，点击才真正摆摊 |

**已上架商品数**：`Info.List` 中 `Status != 4`（4=已下架）的条目数。

## 2. 组队判断与退出

**判断是否在队**（`PlayerManager.playerEntity`）：
```csharp
playerEntity.IsParty()      // 是否组队状态（含临时离队判断）
playerEntity.IsLeader()     // 是否队长
// 队伍列表：PlayerDataHolder.teamData[0].Player.Uid 是队长
```

**退出队伍**（`TeamManager.SendOperation` → `Proto_CS_Team{Type, Id}` → `LSSPROTO_TEAM_FUNC=1012`）：
- **队长** → `SendOperation("解散队伍", m_Uid)`
- **队员** → `SendOperation("离开队伍", m_Uid)`

> 注意：回城按钮 `OnClickRecord` 里判定 `IsParty() && !IsLeader()` 时提示「队员状态下无法操作哟」。若目标是「单人回城 + 单人摆摊」，需在回城**前**把队伍解散/离开，并等待服务器确认队伍状态更新。

## 3. 回城（法兰城）

**按钮**：`OnClickRecord()` → 确认框 → `RoleManager.SendMenu(3, "-1")`

```csharp
SendMenu(int func, string data, string Kuid = "", string callfunc = "")
// → Proto_CS_Menu{Func=3, Data="-1"} → LSSPROTO_MENU_FUNC
```

- 前提：`encounterStatus == 0`（非挂机中）
- 摆摊硬性要求：`playerFromUid.mapId == 0 && playerFromUid.floor == 1000`（法兰城），否则「请前往法兰城摆摊」。回城即回到法兰城，满足该条件。
- 回城是服务端传送，等待落位后 `playerFromUid` 更新为 `mapId=0, floor=1000` 再继续。

## 4. 寻找摊位（瞬移）

**`StallManager.SendStallMessage(m_Uid, "寻找摊位")`** → `Proto_CS_Street{Type="寻找摊位", KUid=uid}` → 1013
- 服务端直接把角色传送到**自己摊位旁**，无需坐标/寻路。
- 管理按钮 case 6 的确认文案「是否飞到摆摊位置？」即此功能。

> 若尚未出摊（Status==3），「寻找摊位」可能无效——所以流程顺序：先回城 → 摆摊/或已有摊位 → 寻找摊位。

## 5. 收摊 → 重摆（重置摊位时间）★ 用户约束

```csharp
SendStallMessage(uid, "收起摊位");   // 收摊（管理按钮 case 3，有确认框）
// 间隔 0.1s
SendStallMessage(uid, "我要摆摊");   // 重新摆下（stallStatus==3 时按钮的动作用）
```

- 收摊 / 摆摊均为服务端动作，客户端间隔 0.1s 后重摆，**免费重置摊位时间**。
- **严禁用「增加时间」（续费）来重置时间** —— `SendStallMessage(uid, "增加时间")` 要花钱（`extendTimePric = info.Pric`），流程**一律不用**。
- **卡位置即停**：若重摆后确认摊位未成功（或「寻找摊位」落位异常/卡住），**立即停止整个流程**，Tip 提示用户手工操作，不重试、不换方案硬顶。
- 摊位名：`Info.Name` 或角色名；若需改名用 `SendStallMessage(uid, "摊位名修改", name)`。

## 6. 读剩余空格数 & 上架

**剩余空格** = `20 − (Info.List 中 Status != 4 的条数)`（客户端上限 20）。

**上架协议**（`OnClickStartSell` / `PutGoodsOnShelf`）：

```csharp
Proto_CS_Street {
  1: string Type = "上架摊位";
  3: Proto_commodityInfoArr List = { List: [ 每个商品 Proto_CommodityInfo ] };
  7: string Id = 摊位名;   // 新建摊位时带上
 99: string KUid = m_Uid;
}
```

每个商品：

```csharp
Proto_CommodityInfo {
  1: string Id = 背包格Index.ToString();  // 道具=GetItemDatasFromUid 下标；宠物=data.Index+1
  2: int    Type = 1;                     // 1=道具
  3: Proto_ItemData Item = itemData.data; // 直接填该格道具数据
  5: int    Pric = 单价;                   // 不能 < 10
  6: int    Status = 2;                   // 在售
  7: int    PricType = 0/1;               // 0=金币 1=钻石
}
```

- 价格下限 10（`PutGoodsOnShelf` 里 `m_UITxt_totalPrice.text < 10` → 「商品价格不能小于10」）。
- 修改价格：`Proto_CS_Street{Type="修改商品", List=[商品]}`。

**两种上架策略**：
1. **一次性**：构造全部可上架商品的 `Proto_CommodityInfo` 列表，一条 `"上架摊位"` 消息全发（简单，但可能一条消息过大/超20上限）。
2. **逐件 + 复查**：每上架一件查询一次摊位状态，更新剩余格数，直到满或无货（慢但稳，与日常/采集提取的节奏式风格一致）。

## 7. 可上架判定（背包道具）★ 用户约束

**只上架「可上架装备表单」里的装备**（`可上架装备表单_默认定价.xlsx` / `gen_craftable_equip_form.py` 生成的 ItemId 集合），**其它任何道具一律不上架**——因为只有表单内装备有定价，表单外的东西找不到价格。

**遍历范围**：`PlayerDataHolder.GetItemDatasFromUid(uid)[8..67]` —— **60 格背包**（0-7 是身上装备，8-67 是背包）。

**每格判定**（`ItemData` 包装 `Proto_ItemData`），全部满足才上架：
- `item.useFlag == 1`（该格有道具）且 `item.data != null`
- **道具 Id 在可上架装备表单的 ItemId 集合内**（首要条件，不在集合 → 跳过）
- **不可上架**（`StallPanel` 里 `com_Item.UseFlag = true` 灰显）当且仅当：
  ```
  Flg.HasFlag(PROTO_ITEM_FLAG_APPRAISAL)   // 未鉴定
  && !Flg.HasFlag(PROTO_ITEM_FLAG_LOGOUT_PASS)
  && !Flg.HasFlag(PROTO_ITEM_FLAG_DICE_PASS)
  && data.Locked == 0
  ```
  即：**未鉴定且无交易保护且未锁定 → 不可上架**（需先鉴定）。
- 已上架的道具（`backItemStatusDic.ContainsKey(index)`）不能重复上架。
- 物品配置 `TbItemConfig.Cansell == false` → 不可交易道具，上架时一并排除（`item_tbitemconfig.bytes` 可解析）。

**宠物**：不在表单范围内（表单只含装备），**宠物一律不上架**。

## 8. 定价（对应可上架表单）

- 依据 `可上架装备表单_默认定价.xlsx`（`gen_craftable_equip_form.py` 生成）：
  - D 级默认价 = `等级² × 1000`
  - C/B/A/S 每高一级 +10%（`round(1.1^n × D)`，取整）
  - 默认金币（`PricType=0`）
- 装备品级：`ItemManager.GetEquipScoreLevel` 按评分百分比映射 1~5（D~S），阈值见 `item_tbequipscorelevelconfig`。
- 默认值只在**第一次配置**时显示，不持久化；用户改价后按用户价。
- **仅表单内装备有定价**；表内无 ItemId 的道具找不到价格 → 直接跳过不上架。

## 9. 坑与注意事项

1. **安全码**：`PutGoodsOnShelf` 检查 `Manager<RoleManager>.Instance.CurrSecurityCodeFlag != 0` → `OpenSecurityCode()`。若角色开了安全码，直接发上架协议可能被服务端拒绝或弹安全码。需前置确认/提示。
2. **挂机状态**：`encounterStatus != 0`（挂机中）回城会被拒（「自动挂机中无法行动」）。流程开始前需停止挂机。
3. **摆摊地点**：必须在法兰城（`mapId==0 && floor==1000`）。回城后需等服务端落位。
4. **寻找摊位前提**：需已出摊（否则无摊位可寻）。首次可：回城 → 直接在法兰城 `"我要摆摊"` → `"寻找摊位"` 落位。
5. **摊位名**：上架时 `Id=摊位名`，用响应里的 `Info.Name`，避免每次上架把名字发空。
6. **节奏式发送**：上架/查询间隔应像日常、采集提取一样用状态机 + 定时器，避免瞬间刷屏（服务器慢时超时重试 2 次再跳过）。
7. **容量**：单次上架列表不能超过 20（客户端上限），剩余格数以服务端 `Info.List` 复查为准。
8. **★ 不续费**：摊位到期**不用「增加时间」续费**（要花钱）。重置时间一律用「收起摊位 → 0.1s → 我要摆摊」（免费）。若重摆后摊位未成功/卡位置，**立即停止流程**并 Tip 提示人工处理，不重试。
9. **★ 只上架表单装备**：背包里不在 `可上架装备表单_默认定价.xlsx` 里的道具、宠物、料理、道具等一律不上架（无定价）。

### 11.2 运行流程（状态机，StepSec=0.4s）

```
检查安全码 → 停止挂机 → 退队 → 回法兰城(mapId==0,floor==1000) →
查摊位状态：1出摊中→寻找摊位→收起摊位→重摆（免费重置时间）
           2到期  →同上（收摊重摆）
           3未摆摊→直接「我要摆摊」→寻找摊位 →
读剩余格位(20−在售数) → 扫描背包[8..67] →
只上架表单内有定价的装备（按运行品质 D~S 取价）→ 分批(≤5)「上架摊位」→
复查格数直至满/无货 → 完成
```

- **不可执行即终止**（不硬顶）：无定价配置 / 检测到二级密码 / 摊位状态异常 / 回城或寻找摊位定位失败 → Tip 并转人工。
- **网络超时最多重试 2 次**：等待服务端回推（约 5.2s）超时后重发同一步，累计 2 次仍未果则终止。
- **每步 Tip**：开始 / 回城 / 摆摊 / 收摊 / 重摆 / 剩余格位 / 每批上架数 / 完成 / 终止，均用 `NotifyManager.Tip`。

### 11.3 IPC（批量自动上架模块预留）

目录与精简桥接一致：`~/.seqchapter_helper/instances/inst_{pid}/`

| 文件 | 内容 |

| `auto_stall_state.json` | `{"running":bool,"phase":"...","items_listed":N,"skipped_no_price":N,"reason":"..."}` |

> 批量上架 = 切换账号后对每个实例写 `start`，轮询 `auto_stall_state.json.running==false` 再切下一个。

### 11.4 改价流程（用户改默认定价.xlsx 后）

1. 编辑 `可上架装备表单_默认定价.xlsx` 的「装备表单」页 D/C/B/A/S 五档价格。
2. `python tools/gen_auto_sell_price_cfg.py` → 重生成 `seqchapter_auto_sell_prices.txt`。
3. 重打补丁：`apply_combo_patch.py` / GUI 会随自动上架 DLL 一起把该 txt 复制到 `cg37_Data/assets/hotfixdata/seqchapter_auto_sell_prices.txt`。
4. 玩家重进游戏后「一键上架」即用新价。

> ⚠ 不要重新运行 `gen_craftable_equip_form.py` 覆盖 Excel（会还原为默认价）。只手动改 Excel 里要调的价格。
